# Wizard conversion backlog, retained 2026-10-13

What `bpk.py from-wizard` refuses today, by family, and what each would need
before it could be supported. Recorded from the independent audit of the
Blueprint Wizard coherent-release plan (2026-10-12, in the owner's ecosystem
hub) so that the Packager's own release notes and capability record can name
it. These are work items, not promises: the next release need not support any
of them, and no refusal here may be removed just to make a conversion succeed.
Expected refusals need fixtures just as successful paths do
(`tests/test_wizard_authoring.py`).

A to C are the demonstrated blockers in the MBA 620 sandbox extraction (seven
date errors, six post-first errors, one quiz refusal). D is a provenance and
recovery path. E to J broaden applicability and stay separate, testable
increments.

| Item | Refusal today (`blueprint_packager/wizard_authoring.py`) | Representation or evidence needed | Acceptance evidence |
| --- | --- | --- | --- |
| **A. Dates and term settings** | `ACTIVITY_SETTINGS_UNSUPPORTED` for `date_due`, `date_start`, `date_end`, `condition_set` | Convert explicit extracted dates into a separate, reviewable settings artifact keyed by stable source identity; keep raw UTC; distinguish due, start and end, absent values and deliberate clearing. Retaining dates or rebasing a term is the author's choice, never inferred from prose. Reuse the calendar and build path where the semantics match (`build.py`). Conditions stay separate. | Round trip explicit dates and absence; partial weeks, time zones and DST, per-activity overrides, stale-date removal; compare re-extracted timestamps; record the author's decisions. |
| **B. Post-first and moderated discussions** | `DISCUSSION_SETTINGS_UNSUPPORTED` | Explicit per-discussion settings and forum/topic ownership. The global `discussion_defaults.must_post_to_participate` path cannot represent mixed values; moderation and forum visibility are distinct settings. | Two topics with differing post-first values, moderation combinations, exact forum joins, extracted-setting equality after rebuild; a tenant check before any live-verified claim. |
| **C. Quiz carry-forward** | `QUIZ_SOURCE_REQUIRED` | The original immutable export or package plus a source hash and an exact quiz identity and manifest mapping; an explicit `Source` directive; the existing carry path (`build.py`). Never reconstruct question XML from the lightweight blueprint or substitute titles for identity. | Original payloads, assets and question-library dependencies verified; grade and placement joins; dates; only authorized transformations; same-title quizzes, missing assets and mismatched hashes refused. Quiz authoring stays in its own lane. |
| **D. Front matter recovery** | `FRONT_MATTER_NOT_EXTRACTED` warning | Preserve missing values; optionally bind an authoritative blueprint or syllabus supplement with provenance and an explicit conflict policy. Never invent a description, materials or outcomes from other text. | Present, missing and conflicting fields; exact authored wording; a source receipt; document-only fields never silently published as pages. |
| **E. Images, files, Creator+ and other media** | `BLOCK_UNSUPPORTED`, `EMBED_UNSUPPORTED` | An asset-bearing authoring package or explicit source references: portable names, original bytes and hashes, alt text and placement, supported embed and practice semantics. A paragraph holding a filename is not enough. | Image-only and linked-image content, duplicate basenames, nested assets, attachments, missing files, embed allow and deny cases, retained Creator+ dependencies; local paths, then tenant rendering and playback where claimed. |
| **F. Nested modules, descriptions, aliases, multiple placements, visibility** | `ROOT_KIND_UNSUPPORTED`, `MODULE_DESCRIPTION_UNSUPPORTED`, `WEEK_VISIBILITY_UNSUPPORTED`, `NESTED_MODULE_UNSUPPORTED`, title/visibility mismatch and multiple-placement errors | Separate object identity from placement identity, alias text and visibility; an explicit hierarchical representation. Do not flatten nested modules or duplicate an object to represent two placements. Descriptions and link bodies kept apart from page content. | One object with two placements, aliases, hidden parents and children, duplicate page basenames, descriptions with links; exact tree and relationship comparisons. |
| **G. Submission types, grade categories, bonus and exclusions, rubric variants** | `SUBMISSION_TYPE_UNSUPPORTED`, `MULTIPLE_RUBRICS_UNSUPPORTED`, `GRADE_SETTINGS_UNSUPPORTED`, rubric settings, shape, weight, score and overall-text errors | Explicit model and build support for each variant rather than normalisation into the individual-file, numeric-grade, percentage-rubric shape. Preserve raw scores and settings; a missing weight is not permission to choose one. | Unlinked and linked grades, category, bonus and exclusion cases, multiple rubric associations, arbitrary supported cell scores, overall feedback, exact reciprocal joins. Reusable serializers go upstream under the promotion process. |
| **H. Checklist multiplicity, categories, unplaced checklists** | `MULTIPLE_CHECKLISTS_UNSUPPORTED`, `CHECKLIST_CATEGORIES_UNSUPPORTED`, `UNPLACED_CHECKLIST_UNSUPPORTED` | Named independent checklist objects, categories and items, item links and dates, explicit placement. Extracted item lists stay distinct from any rule that derives a checklist. | Two checklists in one week, empty and non-empty categories, an unplaced checklist's disposition, preserved order, links and dates; no fabricated derivation rule. |
| **I. Release conditions** | `CONDITIONS_UNSUPPORTED` and per-object `condition_set` | A condition graph tied to the original resource identities with explicit supported operand and operator types. Unsupported cases stay blockers; availability is never inferred from a visible date. | Join integrity, multiple conditions, AND/OR semantics, absent references, cross-object dependencies; tenant evidence per supported family. |
| **J. Rich text, anchors, links and table breadth** | `RUN_FORMAT_UNSUPPORTED`, `LOCAL_ANCHOR_UNSUPPORTED`, `LINK_MARKER_UNREPRESENTABLE`, `TABLE_SHAPE` | Superscript and subscript, explicit anchors and escaping where authoring can preserve them; header rows honoured (done for declared header rows in 0.3.0); a decision on merged and irregular tables rather than flattening without a ledger; rich runs in cells. | Scientific notation, literal reserved marker characters, internal anchors, ordered and nested lists, zero and multiple header rows, links in cells; Word and Google read-back of the supported forms. |
